# About 页面编写指引

这份文件讲的是**怎么给 About 页面写内容**（不是怎么改它的代码 —— 那是 `设计说明.md`）。

写给自己看，也写给 AI 看。下面每一条都与代码一一对应，改代码时请顺手改这里。

---

## 一、这个页面由什么组成

```
┌──────────────────────────────────────────────┐
│   ┌────────┐                                 │
│   │  头像  │  V1rtual          ← 身份区       │
│   └────────┘  ▸ 一句话签名                     │
│  ─────────────────────────────────────────   │
│                                              │
│   正文（你贴的 HTML 在这里渲染）               │
│                                              │
│  ─────────────────────────────────────────   │
│   (标签) (标签) (标签)                        │
│                                              │
│   🐱 » GitHub ↗   » 画廊 ↗   ✉ » 邮箱 ↗       │
└──────────────────────────────────────────────┘
```

| 区块 | 内容从哪来 | 能不能改 |
| --- | --- | --- |
| **头像 + 昵称** | **站点账号**（`user` 表 `id = 0`）的实时值 | ❌ **不能改** —— 在 Profile 页换头像，About 页跟着变 |
| **一句话签名** | 后台 | ✅ |
| **正文** | 后台 | ✅ |
| **标签** | 后台 | ✅ |
| **链接** | 后台 | ✅ |

> **身份区永远显示。** 它的值来自账号，永远有内容，所以不存在「没填就不显示」的情况。

**空态规则**：当**签名、正文、标签、链接四项全部为空**时，内容区显示一句「这里还没有内容」，
身份区照常显示。只要任意一项填了东西，占位文案就消失。

## 二、去哪写

登录 → 个人中心 → 后台 → **「About 页面配置」** 区块。

右边是**实时预览**，和访客看到的**是同一个组件**，所以预览什么样、线上就什么样。

保存后立刻生效（线上刷新即可看到）。

## 三、一句话签名

| | |
| --- | --- |
| 位置 | 昵称下面，青色发光小字，前面自动加一个粉色 `▸` |
| 长度 | **最多 255 个字符** |
| 写法 | 纯文本，**不支持 HTML**。写了标签会原样显示出来 |
| 留空 | 整行不显示 |

**好的例子**：`在代码与幻想之间游荡` · `白天写代码，晚上收星星` · `还在折腾`

## 四、正文（重点）

正文是**唯一支持 HTML** 的字段。它会被一个**白名单过滤器**处理一遍再渲染 —— 只保留认识的标签，
其余一律清掉。这不是为了限制你，是因为这个页面是公开的，而过滤只在渲染前做一次。

### 4.1 支持的标签

| 类别 | 标签 | 说明 |
| --- | --- | --- |
| 段落 | `p` `br` `hr` | |
| 强调 | `strong` `b` `em` `i` `u` `s` `del` `ins` | 加粗 / 斜体 / 下划线 / 删除线 |
| 链接 | `a` | 见 4.3 |
| 图片 | `img` | 见 4.4 |
| 列表 | `ul` `ol` `li` | |
| 标题 | `h1` `h2` `h3` `h4` `h5` `h6` | 青色 Orbitron 字体。正文里**建议从 `h2` 或 `h3` 起**，`h1` 留给页面自己 |
| 引用 | `blockquote` | 左边一条青色竖线 |
| 代码 | `code` `pre` | 行内粉色；`pre` 是黑底块 |
| 容器 | `span` `div` | 只是包一层，本身没有样式 |
| 图文 | `figure` `figcaption` | 图 + 图注 |
| 表格 | `table` `thead` `tbody` `tr` `th` `td` | |

### 4.2 支持的属性 —— 只有这五个

| 标签 | 允许的属性 |
| --- | --- |
| `a` | `href`、`title` |
| `img` | `src`、`alt`、`title` |

**其他标签一个属性都不给。** 特别地：

- ❌ **`class`** —— 给了也没用。页面的样式是「作用域」的，`v-html` 生成的内容拿不到作用域标记，
  你写的 class 不会有任何效果，只会让人困惑
- ❌ **`style`** —— CSS 本身执行不了 JS，但 `style="position:fixed;inset:0"` 能盖住整站做钓鱼页。
  这一条不留口子
- ❌ **`onclick` / `onerror` / `onload` 之类** —— 内联事件属性是真实存在的 XSS 入口

### 4.3 链接的写法

| `href` 写什么 | 结果 |
| --- | --- |
| `https://github.com/xxx` | 正常跳转，**自动新开窗口**，并自动加 `rel="noopener noreferrer"` |
| `mailto:hi@example.com` | 打开邮件客户端，同样新开窗口 |
| `/gallery` | 站内路径，**当前窗口跳转**（不加 `target`） |
| `#top` | 页内锚点 |

**其余一律把 `href` 摘掉**（标签还在，文字还在，只是点不动了）。被摘掉的包括 `javascript:`、
`data:`、`vbscript:` 等等 —— 而且**先去掉空白和控制字符再判断**，所以 `java&#9;script:` 这类
变形写法也挡得住。

> ⚠️ `//evil.com` 和 `/\evil.com` 会被浏览器解析到**外部站点**，所以按外链处理（新开窗口）。

### 4.4 图片的写法

`src` 只允许 `http:`、`https:` 和站内绝对路径 `/…`。`data:` 不给。

**图片得你自己准备** —— 页面上没有图床。两个现成的去处：

- **站点自带的贴纸**：`/stickers/xxx.gif`（`loop1`~`loop16`、`heart2`、`green_stars`、`skull1`、`fox` 等）
- **你自己的 OSS**：后台传图后复制返回的链接

> 记得写 `alt`。它是给读屏软件用的，图挂了也会显示出来。

### 4.5 会被整块删掉的东西

`script` · `style` · `iframe` · `object` · `embed` · `form` · `input` · `button` · `select` ·
`textarea` · `link` · `meta` · `base` · `svg` · `math` · `template` · `noscript`

这些**连里面的内容一起删**。比如贴 `<style>body{display:none}</style>`，结果是什么都没有 ——
不会把 CSS 源码当文字显示出来。

### 4.6 不认识的标签会「脱掉外壳」

比如 `<section><p>正文</p></section>` → `<section>` 被脱掉，`<p>正文</p>` 保留。
所以就算贴了语义化标签，**里面的文字也不会丢**。

### 4.7 两个硬限制

- **嵌套最多 100 层**。超过的部分整块删除。正常写作远远达不到
- **过滤器永不报错**。遇到任何意外都返回空 —— 宁可少显示，不会让页面崩

## 七、链接

### 7.1 三个输入框

每一行链接是：**名称** · **图标 URL** · **网址**

| 字段 | 说明 |
| --- | --- |
| 名称 | 显示的文字 |
| 图标 URL | **留空即可** —— 见下面的自动匹配。填了就优先用你填的 |
| 网址 | 跳转地址。**留空和名称都空的行，保存时会被丢掉** |

渲染出来是 `🐱 » GitHub ↗` —— 图标（如果有）在 `»` 前面。

### 7.2 图标自动匹配

**留空图标栏**，系统会按网址的**主机名**自动配上官方品牌图标：

| 网址里包含 | 图标 |
| --- | --- |
| `github.com` | GitHub |
| `bilibili.com` · `b23.tv` | 哔哩哔哩 |
| `weibo.com` · `weibo.cn` | 微博 |
| `zhihu.com` | 知乎 |
| `x.com` · `twitter.com` | X |
| `youtube.com` · `youtu.be` | YouTube |
| `t.me` · `telegram.org` | Telegram |
| `discord.com` · `discord.gg` | Discord |
| `steamcommunity.com` · `store.steampowered.com` | Steam |
| `pixiv.net` | Pixiv |
| `instagram.com` | Instagram |
| `linkedin.com` | LinkedIn |
| `douyin.com` · `tiktok.com` | TikTok |
| `qq.com` | QQ |
| `music.163.com` | 网易云音乐 |
| **任何 `mailto:` 邮箱链接** | ✉ 信封 |

规则细节：

- **子域名也认**：`gist.github.com` 一样匹配到 GitHub
- **只按整段标签匹配**，所以 `github.com.evil.com` 这种拼接域名**不会**被误认成 GitHub
- **站内相对路径（`/gallery`）不猜图标** —— 没有主机名，就没有图标
- 图标是**单色粉色**（和链接文字同色）。鼠标悬停时文字会变青，但**图标颜色不会跟着变**

### 7.3 手动指定图标

图标栏填什么就显示什么，**优先于自动匹配**：

- 站内现成的：`/stickers/heart2.gif`
- 你自己传的 OSS 链接

> 图标显示尺寸很小（18px 高），**别用大图** —— 一张 1MB 的贴纸缩到 18px 就是一团糊。
> 想要清晰，用 `public/icons/` 里那种 SVG。

## 八、几个坑

1. **图片不会自己出现** —— 正文里的图和图标都得你提供地址，页面上没有图床
2. **别在正文里写 `class` 或 `style`** —— 前者无效，后者会被剥掉
3. **签名不是 HTML** —— 写了 `<b>粗</b>` 会原样显示 `<b>粗</b>`
4. **保存是整体覆盖** —— 没有版本历史，清空某个字段保存后就是真的没了
5. **加载失败时不能保存** —— 如果后台打开时读取配置失败，保存按钮是**禁用**的
   （这是刻意的：否则空白表单会把已有内容覆盖掉）
6. **正文里的行内代码和代码块的区别** —— `<code>` 是粉色行内小字，`<pre><code>` 才是黑底块

## 九、给 AI 的说明

如果你是被要求「帮我把 About 页面写好」的 AI，请遵守下面这些。

### 9.1 数据结构

后台保存的 payload 长这样（字段名必须完全一致）：

```json
{
  "tagline": "在代码与幻想之间游荡",
  "bioHtml": "<h2>关于我</h2><p>…</p>",
  "links": [
    { "name": "GitHub", "url": "https://github.com/xxx", "icon": "" }
  ],
  "tags": ["Java", "Vue", "摄影"]
}
```

- **没有** `avatarSrc` / `displayName` —— 它们来自站点账号，不在这个表单里，也不要生成
- `links` 里的 `icon` 可以为空串，表示走自动匹配
- `tags` 是字符串数组；后台输入框按中英文逗号切分

### 9.2 生成 `bioHtml` 的硬约束

**只用第一节列出的标签和属性。** 具体地：

- ✅ 可以：`p br hr strong em u s del ins a img ul ol li h2…h6 blockquote code pre figure figcaption table thead tbody tr th td`
- ❌ 不要生成：`script` `style` `iframe` `svg` `form` 及任何表单控件 —— 会被整块删掉，白写
- ❌ 不要给**任何**标签加 `class` 或 `style` 属性 —— 前者无效，后者被剥
- ❌ 不要加内联事件属性（`onclick` 等）
- ✅ `a` 只能有 `href` 和 `title`；`img` 只能有 `src`、`alt`、`title`
- ✅ `img` 的 `src` 用 `https://…` 或站内 `/…`，**不要用 `data:`**
- ✅ 链接外链直接写 `https://…`，**不要手写 `target` 或 `rel`** —— 过滤器会自动补
- ✅ 嵌套别超过 100 层
- ✅ 图片地址必须真实存在。不确认真假时，**优先用 `/stickers/` 里现成的贴纸**，
  或者干脆不放图，不要编造 OSS 链接

### 9.3 内容风格

- 页面是**个人简介**，不是产品落地页。第一人称，克制，不要营销腔
- 正文里**不要用 `h1`**（页面自己已经有一处大标题了），从 `h2` 起
- 段落之间用 `<p>` 分开，不要用一堆 `<br>` 硬撑
- 标签控制在 **3~6 个**，太长了会挤成一团
- 链接控制在 **3~6 条**，图标栏留空即可

### 9.4 参考资料

- `设计说明.md` —— 这个页面**为什么**长这样（安全策略、取舍、决策记录）
- 本文件 —— **怎么用**它
- `src/utils/sanitizeHtml.js` —— 过滤器的实际实现，是白名单的最终事实来源
- `src/views/about/brandIcons.js` —— 图标匹配表的事实来源
