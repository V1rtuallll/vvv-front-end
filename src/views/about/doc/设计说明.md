# About 页面设计说明

## 目标

在左侧导航加入 About 入口，指向一个**公开的个人简介页**。页面版式固定，其中三个区域的内容
可以在后台管理界面编辑：

| 区域 | 内容 |
| --- | --- |
| 身份区 | 头像 URL、昵称、一句话签名 |
| 正文区 | 多段正文，支持**基础 HTML** |
| 链接 · 标签区 | 社交链接列表（可增删排序）、技能/兴趣标签 |

与 `Profile` 页不冲突：`Profile` 是需登录的用户中心，About 是面向所有访客的自我介绍页。

## 决策记录

讨论过四种渲染方案，最终**都没有采用**：

| 方案 | 为什么不用 |
| --- | --- |
| iframe 沙箱渲染整页代码 | 自由度高，但数据是一坨 HTML —— 以后想改样式得重贴代码，移动端要自己写 media query |
| `v-html` 渲染片段 | `<script>` 不执行看似安全，但 **`<img onerror="…">` 这类内联事件属性会执行**，且跑在主文档里，能读 `localStorage` 里的 token；贴的 `<style>` 还会串到整站 |
| `v-html` + 手动执行 script | 与上者同样的暴露面，还要处理路由切换时脚本重复执行、监听泄漏 |
| 富文本编辑器 | 做不到自定义设计，且要新引一个编辑器依赖 |

**选定方案：固定版式 + 结构化字段**。数据是字段而不是 HTML 字符串，因此改样式不用重贴内容、
移动端能自动适配、也不会因为一次笔误把整站样式弄坏。正文区仍然支持基础 HTML，覆盖
「想写得花一点」的需求。

以下内容**明确不做**（YAGNI）：自由 HTML 区块、Markdown 渲染、图标库、独立的头像上传通道、
链接的关系表、草稿与版本历史、多语言。

## 数据模型

新增单行表 `about_page`（`id = 1`），与 `home_config` 同属「站点全局唯一配置」这一类，
沿用同一套 `REPLACE INTO` 写法。

迁移文件：`db/migrations/V003__about_page.sql`

```sql
CREATE TABLE `about_page` (
  `id`           bigint       NOT NULL AUTO_INCREMENT,
  `avatar_src`   varchar(512) DEFAULT NULL COMMENT '头像URL',
  `display_name` varchar(100) DEFAULT NULL COMMENT '昵称',
  `tagline`      varchar(255) DEFAULT NULL COMMENT '一句话签名',
  `bio_html`     mediumtext            COMMENT '正文原文',
  `links_json`   text                  COMMENT '链接列表JSON',
  `tags_json`    text                  COMMENT '标签JSON',
  `updated_at`   datetime     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`)
) ENGINE = InnoDB CHARSET = utf8mb4 COLLATE = utf8mb4_unicode_ci;
```

MySQL 5.6 兼容性（生产库是 5.6.50，必须逐条确认）：

- `mediumtext`、`bigint`（不带显示宽度）、`utf8mb4_unicode_ci` 均可用
- `datetime ... ON UPDATE CURRENT_TIMESTAMP` 可用，且 `home_config` 已在用同一句
- **不能用 `JSON` 类型**（5.7+ 才有）→ 链接与标签存 `text`，与现有的 `gallery_json` 一致

链接与标签**不建关系表**：数量在个位数，JSON 数组足够。

### 存原文，渲染时过滤

`bio_html` 存用户输入的**原文**，不做保存时清洗。理由：保存时清洗会让编辑器里显示的内容
被静默改写，用户无法预期。

安全由**收敛到唯一出口**保证：全仓库只有 `components/SafeHtml.vue` 允许出现 `v-html`，
过滤逻辑封装在该组件内部。仓库实现前 `v-html` 引用数为零，因此加了一条守卫测试，
扫描 `src/**/*.vue`，除 `SafeHtml.vue` 外出现 `v-html` 即失败。

**已知边界，用户已裁决接受、刻意不修**：`SafeHtml` 是单根组件且未关闭 `inheritAttrs`，
调用方写 `<SafeHtml :innerHTML="…" />` 时 Vue 会把值直接设到根元素的 `innerHTML`，过滤器不被调用；
而守卫只搜字面量 `v-html`，这种写法不会触发它。内容只有单一作者，触发需要将来的开发者写错代码，
不属于真实威胁，因此不做结构性加固。**组件里「调用方无从绕过」的说法在这个路径下不成立。**

## 安全策略：`sanitizeHtml`

实现为纯函数 `src/utils/sanitizeHtml.js`，零依赖，用浏览器自带的 `DOMParser`。

```js
const doc = new DOMParser().parseFromString(html, 'text/html');
```

`DOMParser` 生成的是**惰性文档**：图片不会发起加载、脚本不会执行。这是整个方案安全性的基础，
不依赖任何过滤规则的正确性。

### 遍历规则

| 类别 | 处理 |
| --- | --- |
| 白名单标签 | 保留，但**移除全部属性**，再按下方规则补回允许的属性 |
| 危险标签 | **连同子树一起删除** —— `script`、`style`、`iframe`、`object`、`embed`、`form`、`input`、`button`、`select`、`textarea`、`link`、`meta`、`base`、`svg`、`math`、`template`、`noscript` |
| 其他未知标签 | **展开（unwrap）**：删掉标签本身，保留其子节点 |

`script` / `style` 必须**连内容一起删**，不能展开 —— 否则 JS 源码会变成页面上的可见文字。
`svg` / `math` 是外来内容（foreign content）的经典 XSS 载体，一并删除。

**白名单标签**：

```
p br hr strong b em i u s del ins
a img
ul ol li
h1 h2 h3 h4 h5 h6
blockquote code pre
span div
figure figcaption
table thead tbody tr th td
```

**允许的属性**只有四个：

```
a[href]  a[title]
img[src] img[alt]  img[title]
```

其他标签一个属性都不给。**故意不给的两样**：

- `class` —— 给了也没用，Vue 的 `scoped` 样式作用不到 `v-html` 生成的内容上
- `style` —— CSS 本身执行不了 JS，但 `position:fixed;inset:0` 能覆盖整站做钓鱼

### 协议校验

**这条在实现后的评审中被实测纠正过，原文的因果说反了。**

真正拦住 `java\tscript:alert(1)` 的是**正向协议白名单**，不是归一化：把归一化削弱到「只去空格」，
整套测试照样通过 —— 因为 `java\tscript:` 本来就不以 `http:` / `https:` / `mailto:` 开头。
归一化因此是**纵深防御**而非主防线，保留它是为了不依赖「白名单永远够用」这条推理在将来仍然成立
（`java&#9;script:` 这类实体编码变体也归它兜底）。

判定收敛在单个函数，返回 `blocked` / `local` / `external` 三态，`href` 的保留与 `target`/`rel`
的补全读同一个结果，避免两处判断各自漂移。

| | 允许 |
| --- | --- |
| `a[href]` | `http:`、`https:`、`mailto:`、站内绝对路径 `/…`、锚点 `#…` |
| `img[src]` | `http:`、`https:`、站内绝对路径 `/…` |

其余一律剔除该属性（不是删除元素）。

**`//host` 与 `/\host` 归为 external**：浏览器会把它们解析到外部站点，所以要走外链规则。
只有单个 `/` 开头的算 `local`。

`a` 的处理：外链强制补 `target="_blank" rel="noopener noreferrer"`，站内路径与锚点保持原样。

### 两条运行契约

- **深度上限**：遍历有层数上限，超过的子树**整个删除**（而不是放行）。没有上限时约两千层嵌套
  就会抛 `RangeError`，把整个渲染搞崩
- **永不抛异常**：任何意外都返回空串。安全边界不能有「抛出去」这个选项 ——
  调用方一旦 `try/catch` 之后回退成原始字符串，过滤器就等于没做

## 接口契约

只新增两个接口。

```
GET  /api/about        公开，供 About 页面与后台表单回显
POST /api/admin/about  OwnerAccess 校验，后台保存
```

后台表单回显复用公开的 GET —— 回显的是本来人人可见的内容，不需要额外权限，少一个接口少一份测试。

`AdminAboutController` 沿用 `AdminHomeConfigController` 的形状：`OwnerAccess` 拒绝时返回
`Result.error(403, DENIED_MESSAGE)`，与鉴权层的响应一致。公开的 `AboutController` 不做权限判断。

**`SecurityConfig` 必须同时修改。** 当前是白名单制：

```java
.requestMatchers("/api/home/**", "/api/user/count", …).permitAll()
.anyRequest().authenticated()
```

新接口不写进白名单，`GET /api/about` 就是 401，About 页面会对所有人空白。这与
「`CorsConfig` 漏一个域名导致全部写操作 403」是同一类配置遗漏，因此配套写测试：
未登录访问 `/api/about` 断言状态码不是 401 / 403。


### 关于 `about-bio.css` 的非 scoped 破例

正文的渲染样式不放在 `index.vue` 的 `<style scoped>` 里，而是放在非 scoped 的
`about-bio.css`，每个选择器都以 `.about-bio` 打头做限定。

理由是 `scoped` 的样式根本作用不到 `v-html` 生成的内容上，而**后台预览必须与真实页面长得
完全一致**，「所见即所得」才成立。About 页面与后台表单共用这一份样式文件。

### Backend 结构

```
controller/AboutController.java                公开 GET
controller/admin/AdminAboutController.java     Owner POST
service/about/AboutQueryService.java           读 + JSON 反序列化
service/admin/AdminAboutService.java           写 + JSON 序列化
mapper/AboutPageMapper.java                    注解 SQL，无 XML
entity/AboutPage.java
vo/AboutVO.java  ·  vo/AboutSaveVO.java  ·  vo/AboutLinkVO.java
db/migrations/V003__about_page.sql
```

`links` 用类型化的 `List<AboutLinkVO>`（字段 `name` / `url`），不用 `Map` —— 类型化的更好测。

`links_json` / `tags_json` 解析失败时**不抛 500**，返回空列表并记日志。

全部复用站点现有的视觉变量，不引入新色系。

| 元素 | 取值 | 来源 |

| 主内容面板 | `rgba(10, 0, 20, 0.85)`、圆角 20px、青粉双色外辉 | `.vf-main` |
| 霓虹四色 | `#ff00ff` 品红、`#00ffff` 青、`#ff69b4` 粉、`#9370db` 紫 | `.glitch-title` 渐变 |

| 后台卡片 | `rgba(5, 5, 20, 0.6)`、`1px solid #00ffff44`、圆角 12px | `.admin-section` |

### 四个区块

1. **身份区** —— 桌面左右布局，头像 160px 圆形 + 青粉双色发光环，右侧昵称与签名，`align-items: center`。
   昵称用 `Monoton`/`Orbitron` 渐变字（与站点其他标题一致），签名用 `Rajdhani` 青色发光。
2. **正文区** —— 渲染 `bio_html`。行高 1.9，颜色 `#c9c9dd`；链接青色发光 hover 转粉；
   图片自适应宽度带青边；引用左侧 3px 青色竖线；`code` 粉色等宽。
3. **标签区** —— flex 自动换行，每项为胶囊：`border: 1px solid #00ffff55; border-radius: 999px`。
4. **链接区** —— 一行 flex，每项 `» 名称 ↗`，粉色，hover 转青并发光。

### 状态

| 状态 | 表现 |
| --- | --- |
| 加载中 | 昵称位置显示 `Loading...`（沿用右侧音乐播放器的惯例） |
| 某区块未填 | **整块不渲染**，不留空标题 |
| 全部未填 | 显示中性占位文案「这里还没有内容」 |
| 加载失败 | 页面渲染空版式，**不额外弹提示** —— `utils/request.js` 已经弹过后端消息 |

### 导航位置

在 `DefaultLayout.vue` 的左侧导航**追加在最后**：`Home / Profile / Gallery / About`，
不动现有三项的顺序。

### 移动端（≤768px）

身份区由左右布局改为上下居中堆叠；头像缩到 110px；面板内边距收到 18px；
标签与链接自动换行。

## 后台表单 `AboutConfigForm.vue`

作为独立 section 加在 `views/admin/index.vue` 的 `HomeConfigForm` 下方，样式沿用 `.admin-section`。

**这个组件是自包含的**：它内部用 `useAboutConfig()` 自己加载、自己保存，父组件只放一个 `<AboutConfigForm />`
标签，没有 props 也没有 emits。这与 `HomeConfigForm` 不同，是有意的 —— 那份配置的状态还要和资源列表联动，
所以由 `useAdminPage` 持有；About 这份状态只有这个表单用，多一层 prop/emit 往返没有收益。

保存接口 `saveAdminAbout` 放在 `modules/admin/api/adminApi.js`，跟随仓库已有的「公开 / 后台」拆分
（`homeApi.js` 对 `adminApi.js`）。

| 字段 | 控件 |
| --- | --- |
| 头像 URL | 输入框 + 缩略预览 |
| 昵称 | 输入框 |
| 一句话签名 | 输入框 |
| 正文 | `<textarea>`，右侧并排**实时预览** |
| 链接 | 结构化列表，每项「名称 + URL」，带上移 / 下移 / 删除，「+ 添加一条」 |
| 标签 | 单个输入框，逗号分隔 |

**实时预览与 About 页面共用同一个 `<SafeHtml>` 组件和同一份 `about-bio.css`**，这是
「直接把页面代码放进去就能看见渲染结果」这一诉求的落点。

保存成功后 `window.$vmessage.success('About 配置已保存')`；`catch` 里**只做状态回滚不弹提示**
（沿用 `useAdminPage.js` 的约定，避免与 `request.js` 重复提示）。

## 发布顺序

这是**联动改动**，两个仓库必须使用同名分支，且两端 CI 都绿才算可上线。

```
后端先发（迁移 V003 + 新接口）→ 验证 GET /api/about → 前端后发
```

后端必须先发：前端 About 页面依赖 `GET /api/about`，反序发布会让页面 404。
迁移由 `deploy.yml` 自动执行，不需要手动跑生产。
