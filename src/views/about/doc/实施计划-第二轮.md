> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 身份区改为读站点账号（不再单独存）、链接支持图标、后台预览改为整页预览。

**Architecture:** 后端把 `about_page` 的两列身份字段删掉，About 页面改成读 `user` 表 id=0 的实时头像与用户名；`links_json` 增加一个可选的 `icon` 字段（JSON 文本，不动表结构）。前端把页面的四个区块抽成 `AboutContent.vue`，About 页面与后台预览共用同一个组件。

**Tech Stack:** Spring Boot 3.5.9 / Java 21 / MyBatis 注解 SQL / MySQL 5.6（生产）/ Vue 3 `<script setup>` / Vitest

**设计依据：** `vvv/src/views/about/doc/设计说明.md`（第一轮的文档，本轮的改动以本文件为准）

```sql
-- =============================================================================
-- V004 — about_page 删掉身份两列
-- =============================================================================
--
-- 做了什么
-- --------
--   删除 about_page.avatar_src 与 about_page.display_name。
--
-- 为什么
-- ------
--   About 页面的头像与昵称改为直接读站点账号（user 表 id = 0）的实时值，
--   这两列不再有任何写入方。留着它们会让实体字段、Mapper 的 NULL 分支和契约测试
--   都围着两个死列转，而且这张表存的东西不再等于「用户真正在编辑的东西」。
--
--   取舍：以后若要给 About 页单独设一个昵称，需要再加回来。
--
-- 兼容性
-- ------
--   ALTER TABLE ... DROP COLUMN 在 MySQL 5.6 与 8.x 上都可用。
--   两列都可空、无默认值、未被任何索引引用，删除不影响其它结构。
--
-- 不往 schema_migrations 写记录：db/migrate.sh 会写。
-- 本文件执行过一次之后不要修改（运行器锁 SHA-256）。
-- =============================================================================

ALTER TABLE `about_page`
  DROP COLUMN `avatar_src`,
  DROP COLUMN `display_name`;
```

```java
package com.v1rtual.vvv_backend.service.user;

import org.apache.commons.lang3.StringUtils;
import org.springframework.stereotype.Component;

import com.v1rtual.vvv_backend.entity.User;
import com.v1rtual.vvv_backend.service.UserService;

import lombok.RequiredArgsConstructor;

/**
 * 站点账号（user 表 id = 0）的头像与用户名。
 *
 * About 页面的身份区直接读这里的实时值，不再单独存一份 ——
 * 在站点上换了头像，About 页跟着变。
 */
@Component
@RequiredArgsConstructor
public class SiteOwnerProfile {

  public static final long ACCOUNT_ID = 0L;
  public static final String DEFAULT_AVATAR = "/default-avatar.gif";
  public static final String DEFAULT_USERNAME = "V1rtual";

  private final UserService userService;

  /** 一次查询取回两个值，避免调用方各查一次 */
  public Identity identity() {
    User owner = userService.findById(ACCOUNT_ID);
    return new Identity(avatarOf(owner), usernameOf(owner));
  }

  private String avatarOf(User owner) {
    return owner != null && StringUtils.isNotBlank(owner.getAvatar())
        ? owner.getAvatar()
        : DEFAULT_AVATAR;
  }

  private String usernameOf(User owner) {
    return owner != null && StringUtils.isNotBlank(owner.getUsername())
        ? owner.getUsername()
        : DEFAULT_USERNAME;
  }

  public record Identity(String avatar, String username) {
  }
}
```

其中 `previewContent` 是 computed：正文取 `form.bioHtml`（实时），链接取当前 `form.links`，标签取 `form.tags`，而 `avatarSrc` / `displayName` 取**加载回来的** `content.value`（它们来自站点账号，表单不编辑）：

```js
const previewContent = computed(() => ({
  avatarSrc: content.value.avatarSrc,
  displayName: content.value.displayName,
  tagline: form.tagline,
  bioHtml: form.bioHtml,
  links: form.links,
  tags: form.tags,
}));
```

`.preview-frame` 的样式模仿站点的 `.vf-main`：`background: rgba(10, 0, 20, 0.85); border-radius: 20px; padding: 24px; max-height: 420px; overflow-y: auto;`，窄屏下把 `padding` 收到 `16px`。

> 注意：`AboutConfigForm.vue` 里**不要**出现 `v-html` 这四个字。

## 发布

两个仓库联动，仍是**后端先发 → 验证 `GET /api/about` → 前端后发**。
`V004` 由 `deploy.yml` 在切换 `current` 之前自动执行。

### ⚠️ V004 是删列，发布窗口有几秒钟的不一致

发布脚本的顺序是「**跑迁移 → 切 `current` → 重启服务**」。切之前旧后端还在服务，
而 `V004` 已经把两列删掉了。具体影响：

| 路径 | 窗口内会发生什么 |
| --- | --- |
| 读（`GET /api/about`） | **不受影响** —— 用的是 `SELECT *`，缺列只会让实体字段为 null，而新代码本来就不读这两列 |
| 写（`POST /api/admin/about`） | **会报错** —— 旧代码的 `REPLACE INTO` 列清单里点名了 `avatar_src` 与 `display_name`，删掉后是「未知列」（1054） |

几秒钟的窗口、只有一个作者、而且只在恰好这时点保存才会撞上。**可以接受**，但要知道：

- 万一真撞上，后台会弹一条错误提示，**数据不会坏**（那次写入根本没执行）
- 如果不想冒这个险，标准做法是**分两次发**：先发一版「不再写这两列」的后端，确认上线后再发 `V004` 删列。
  本次不采用，因为代价（多一次发布）大于收益（几秒钟的窗口）

**顺序不能反的另一点**：前端依赖 `GET /api/about` 返回的身份字段，所以前端不能先发。
