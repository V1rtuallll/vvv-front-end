# 移动端抽屉适配设计说明

## 目标

手机端（≤768px）能直接看到导航（含 About）与音乐播放器，不需要滚过整页内容。

当前的问题是**排序**而不是「少了一套样式」：`DefaultLayout.css` 在 ≤768px 把两个侧栏按
`order: 2` / `order: 3` 排到了主内容之后，导航和播放器因此落在页面最底部。

本方案不改 PC 布局，只改 ≤768px 的表现形式。

## 现状（改动前）

全站只有**一套 DOM + 一套响应式 CSS**，没有任何 `v-if="isMobile"`、UA 判断或移动端专属组件。
`DefaultLayout.css` 的分档注释已经写明这个策略：

```
三档布局策略，桌面样式作为大屏变体，不另建页面：
- <=1024px：收窄左右侧栏与间距，仍保持三栏
- <=768px：改为单栏纵向排列，主内容在侧栏之前
- <=480px：进一步收紧内边距与字号
```

≤768px 时 `.vf-container` 变成 `flex-direction: column`，并给子项编号：

| 选择器 | 值 | 结果 |
| --- | --- | --- |
| `.vf-main` | `order: 1` | 主内容排第一 |
| `.sidebar.left` | `order: 2` | 导航（含 About）被排到内容之后 |
| `.sidebar.right` | `order: 3` | 音乐播放器排在最后 |

三栏的物理宽度是 `grid-template-columns: 250px 1fr 300px` 加 30px 间距，最少需要约 900px。
375px 宽的手机上「侧栏 + 内容 + 播放器」在数学上不成立，因此移动端必须让两个侧栏脱离文档流。

## 决策记录

| 方案 | 为什么不用 |
| --- | --- |
| 保持三栏，只缩小尺寸 | 375px 宽放不下三栏，栏宽会压缩到不可读 |
| 只把导航的 `order` 提前，播放器留在最后 | 改动最小，但导航会随页面滚走，播放器仍要滚到底 |
| 顶部粘性导航条 + 底部迷你播放条 | 竖向吃掉约 90px；播放器的 CRT 大表盘在迷你形态下要重新设计 |
| 把两个侧栏塞进同一个竖向抽屉 | 两者是 `.vf-container` 的并列兄弟节点。不重构 DOM 就只能用固定 `top` 值硬凑，写死第一个的高度后，它内容一变就错位 |
| **两个独立抽屉（选定）** | 各自 `top: 0; bottom: 0`，互不依赖对方高度 |

**明确不做**（YAGNI）：抽屉内嵌搜索、拖拽手势开合、播放器迷你形态、自定义抽屉宽度。

## 交互模型

单个状态驱动两个抽屉：

```js
openDrawer: ref(null)   // null | 'nav' | 'player'
```

同一时刻最多打开一个。

| 操作 | 结果 |
| --- | --- |
| 点左上角 `☰` | 切换导航抽屉（`.sidebar.left` 自左侧滑入） |
| 点右上角 `♪` | 切换播放器抽屉（`.sidebar.right` 自右侧滑入） |
| 再点同一个按钮 | 关闭 |
| 点遮罩 | 关闭 |
| 按 `Esc` | 关闭 |
| 路由变化 | 关闭 |
| 视口回到 >768px | 关闭 |

两个触发按钮用 `position: fixed`，不用 `absolute` 挂在 header 上：手机上向下滚动时 header 会滚出
视口，按钮跟着消失，抽屉就再也打不开了。

视口回到宽屏时必须主动关闭：否则会残留遮罩与 `body` 滚动锁，而宽屏下按钮被 CSS 隐藏，用户无法自救。

## 关键技术约束

### 一、抽屉显隐只能用 CSS，不能给侧栏或播放器加 `v-if`

`src/modules/player/composables/useAudioPlayer.js` 在 `onMounted` 里直接对 8 个 ref 取属性：

```js
audio.volume = 0.3;
playButton.addEventListener("click", ...);
trackNameElement.textContent = formatTrackName(...);
```

其中任何一个为 `null` 都会抛异常，**播放器在全部分辨率下失效**。因此抽屉的收起必须是
`transform` 位移，元素始终留在 DOM 中。

`v-show` 是安全的（它保留 DOM），`v-if` 不是。

现有 `DefaultLayout.test.js` 把整个 `useAudioPlayer` 替换成了空 ref，正好会掩盖这个风险，
所以另加一条使用真实 composable 的守卫断言。

### 二、`subtle-sidebar-glitch` 动画会盖掉抽屉的 `transform`

`.sidebar` 当前的动画声明：

```css
animation: sidebar-glow-breath 10s infinite ease-in-out,
  subtle-sidebar-glitch 8s infinite ease-in-out;
```

而 `subtle-sidebar-glitch` 的内容是：

```css
@keyframes subtle-sidebar-glitch {
  0%, 90%, 100% { transform: translate(0); }
  92%           { transform: translate(-2px, 2px); }
  ...
}
```

**CSS 动画的优先级高于普通声明**，所以抽屉如果直接写 `transform: translateX(-100%)`，会被这段
动画整段覆盖，结果是抽屉永远关不上，还会每 8 秒抖动一次。

≤768px 下必须把 `.sidebar` 的 `animation` 覆盖为只保留 `sidebar-glow-breath`
（它只动 `box-shadow`，不碰 `transform`）。这条**必须带注释说明原因** —— 否则以后有人把它当作
冗余动画清理或加回去，抽屉会静默失效，且没有任何测试能发现。

顺带收益：`box-shadow` 呼吸动画作用在满屏高度的固定面板上，移动端 GPU 开销不小。这与
`DefaultLayout.css` 里已有的判断一致（「移动端固定背景影响滚动性能，改为随内容滚动」）。

### 三、`position: fixed` 不会被祖先劫持

已确认 `.vf-layout` 与 `.vf-container` 都没有 `transform` / `filter` / `will-change` / `contain` /
`perspective`，因此 `.sidebar` 的 `position: fixed` 相对视口定位，符合预期。
`.vf-layout` 的 `overflow-x: hidden` 也不会裁剪 fixed 后代。

## 视觉设计

沿用现有霓虹变量，不引入新色系。

### 触发按钮

默认 `display: none`，仅 ≤768px 显示。44px 见方（与 ≤768px 下 `.nav-link` 的 `min-height: 44px`
同一触摸目标标准）。

按钮内容是单个符号，必须补无障碍属性：

```html
<button
  class="drawer-toggle nav"
  aria-label="打开导航"
  :aria-expanded="openDrawer === 'nav'"
  @click="toggleDrawer('nav')"
>
  ☰
</button>
```

播放器按钮同理，`aria-label="打开音乐播放器"`，`aria-expanded` 对应 `'player'`。
文案用中性表达，与仓库既有约定一致。

```css
.drawer-toggle {
  display: none;
  position: fixed;
  top: 12px;
  z-index: 940;
  width: 44px;
  height: 44px;
  align-items: center;
  justify-content: center;
  font-size: 1.4rem;
  color: #00ffff;
  background: rgba(10, 0, 20, 0.9);
  border: 1px solid #00ffff88;
  border-radius: 10px;
  backdrop-filter: blur(6px);
  cursor: pointer;
}
.drawer-toggle.nav { left: 12px; }
.drawer-toggle.player { right: 12px; }
```

### 抽屉

```css
@media (max-width: 768px) {
  .sidebar {
    position: fixed;
    top: 0;
    bottom: 0;
    width: min(320px, 84vw);
    overflow-x: hidden;
    overflow-y: auto;
    overscroll-behavior: contain;
    padding-bottom: calc(25px + env(safe-area-inset-bottom));
    z-index: 920;
    /* visibility 必须参与过渡：收起时它要在滑出动画结束后才生效，
       否则抽屉会在滑到一半时突然消失 */
    transition: transform 0.28s ease, visibility 0.28s ease;
    visibility: hidden;
    /* 原因见「关键技术约束」第二条 */
    animation: sidebar-glow-breath 10s infinite ease-in-out;
  }
  .sidebar.left { left: 0; transform: translateX(-100%); }
  .sidebar.right { right: 0; transform: translateX(100%); }
  .sidebar.is-open { transform: translateX(0); visibility: visible; }
}
```

`visibility: hidden` 不是装饰性的，它承担一个实际职责：`translateX(±100%)` 只把抽屉移出视口，
元素仍在 Tab 顺序里，键盘可以聚焦到看不见的导航链接。`visibility: hidden` 会把整棵子树移出
Tab 顺序，而 `visibility` 是可以过渡的离散属性 —— 收起时在动画结束后才隐藏，展开时立即显示。

不用 `inert` 属性做这件事：`.sidebar` 在宽屏下是**正常可见**的普通列，`inert` 无法按断点绑定，
绑上去会让桌面端的导航也失去可聚焦性。纯 CSS 的 `visibility` 天然只作用于 ≤768px。

### 遮罩

```css
.drawer-backdrop {
  position: fixed;
  inset: 0;
  z-index: 900;
  background: rgba(0, 0, 0, 0.72);
  backdrop-filter: blur(2px);
}
@media (min-width: 769px) {
  .drawer-backdrop { display: none; }
}
```

宽屏下再隐藏一次是冗余保险：`openDrawer` 在宽屏本不该被打开，双保险避免「视口回落关闭」失效时
在桌面上留下遮罩。

## z-index 规划

现有层级：`VMessage` / Profile 预览 `9999` → Gallery 弹窗 `999 / 1000 / 1100` → 布局内部 `1 ~ 10`。

抽屉插在中间，全部低于弹窗：

| 元素 | z-index |
| --- | --- |
| `.drawer-toggle` | 940 |
| `.sidebar`（抽屉态） | 920 |
| `.drawer-backdrop` | 900 |

抽屉开着时弹出 Gallery 弹窗，弹窗仍盖在最上层，因此不需要改动任何现有弹窗文件。

## 对 ≤768px 现有规则的增删

删除（抽屉里导航恢复竖排，不再需要横向排列与排序）：

- `.sidebar.left { order: 2 }`
- `.sidebar.right { order: 3 }`
- `.left .vf-nav { display: flex; flex-wrap: wrap; gap: 8px }`
- `.left .nav-link { flex: 1 1 96px; margin: 0; min-height: 44px; ... }`

保留：`.vf-container` 的 `flex-direction: column`、`.vf-main` 的 `padding`、`.music-player` 的
`margin-bottom`、`.neon-footer` 的 `margin-top`。

两个侧栏改为 `position: fixed` 后脱离文档流，`.vf-container` 里只剩 `.vf-main` 参与排布，
因此 `.vf-main { order: 1 }` 失去意义，一并删除。

### `useDrawer.js`

复用 `@/utils/responsive` 已有的 `isNarrowViewport()`（当前无人调用）判断视口宽度，断点取自同文件
的 `NARROW_VIEWPORT_WIDTH`，也让该函数获得实际用途。沿用 `responsive.js` 的依赖注入写法
（`win = resolveWindow()`），便于测试传入替身。

**768 这个断点只在 JS 侧是单一来源。** CSS 读不到 `NARROW_VIEWPORT_WIDTH`，
`DefaultLayout.css` 里仍然硬编码 `@media (max-width: 768px)` 与 `@media (min-width: 769px)`。
改断点时两边都要改，只改常量或只改 CSS 会让 JS 的视口判断与 CSS 的显隐判断错位。

职责：开合状态、`Esc` 监听、`body` 滚动锁、视口回落关闭、卸载清理。**不引入 vue-router 依赖** ——
路由变化的监听放在 `DefaultLayout.vue`，`useDrawer` 保持与路由无关。

## 已知边界

- **抽屉开着时切歌仍需先开抽屉**。这是两个独立抽屉方案的固有代价，已裁决接受。
- **`subtle-sidebar-glitch` 在移动端不再生效**。桌面端的抖动效果保留不变，移动端改为静态发光阴影。
- **`@keyframes sidebar-glow-breath` 与 `subtle-sidebar-glitch` 在 `DefaultLayout.css` 中各重复定义了
  两遍**（528/615、543/629），内容完全一致，后一份生效。本次只覆盖 `animation` 引用，不删除重复定义
  —— 删除属于无关清理，若要做另开一次改动。
- 本次不涉及「默认头像」。`/default-avatar.gif` 在前后端两个仓库中都不存在，所有无头像用户当前显示
  裂图，该问题另行处理。
